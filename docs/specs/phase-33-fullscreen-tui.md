# Phase 33：全屏 TUI 规格书

> 状态：已完成（2026-10-19；四项按建议）。用户已在 Windows Terminal 真机验收通过；实施偏差见文末「实施记录」。
> 对应 roadmap 阶段：Phase 33
> 起因：调整终端宽度时输入框留下残影（用户报告，2026-10-19）。在主屏幕上改了三版之后确认：只要内容在主屏幕上，窗口变窄时终端就会立即把它重新折行，程序无论重绘多快都盖不住这一瞬间。pi 1.2、Codex、Reasonix 都缺省全屏。

## 目标

tau 的 TUI 现在跑在主屏幕上：写完的内容交给终端的滚动记录，只有底部一块原地重绘（P25，D31）。这样有几个改不掉的毛病：

- 窗口变窄时，终端立刻把屏幕上已有的内容（包括占满整行的输入框边框）重新折行，留下残影；
- 已经写进滚动记录的历史保持旧宽度的折行，变窄后参差不齐；
- 历史不归程序管，没法在里面搜索，调整宽度后也没法按新宽度重排。

P33 完成后，tau 缺省在**全屏模式**下运行：

1. **备用屏幕，关掉自动换行**：窗口变窄时，超出部分先被裁掉，tau 按新宽度重画完再显示，不会出现折行残影。整个画面只有一屏高，每次重画都包在同步输出里，不闪。
2. **对话由 tau 自己管**：历史显示在可滚动的视图里，用滚轮、PgUp、PgDn 翻看；有新内容时自动跟到底部，往上翻时停住，并提示有多少新内容。调整宽度后，整段对话按新宽度重新排版。
3. **退出时把对话留在终端里**：离开备用屏幕后，按退出时的宽度把整段对话写到主屏幕，留在终端的滚动记录里，和 pi 的做法一样（`fullscreenExitOutput: "transcript"`）。
4. **inline 模式保留**：`tau --inline` 或设置 `tui.mode: "inline"` 时，仍然是现在主屏幕上的界面（包括 P32 之后的调整宽度修补）。

## 设计

### 33a 块渲染成文本行（两种模式共用）

```ts
/** One block as the rows it takes at this width: wrapping, hanging indents and the blank line above it included. */
export function blockLines(block: Block, options: RenderOptions): StyledLine[];

/** Rows of finished blocks, cached by block id and the options that change their rows (width, verbose, showReasoning). */
export class LineCache {
	lines(block: Block, options: RenderOptions): StyledLine[];
	clear(): void;
}
```

- `blockLines` 是纯函数，自己做折行（按单元格宽度，中日韩字符算 2），以及前缀列的悬挂缩进（`›`、`●`、`⎿` 之后的续行对齐到内容列）。它替代现在 `BlockView` 里靠布局引擎完成的部分。
- **样子不变**：inline 模式也改用 `blockLines` 渲染（`<Static>` 里一行一个 `<Text>`），所以两种模式看起来一样。验收时拿改造前后的渲染结果逐行对比（Markdown、代码块、表格、工具卡片、差异、推理、提示、子代理、中文长行）。
- 已完成的块不会再变，按 (块 id, 宽度, verbose, showReasoning) 缓存；正在变化的块每帧现算，它们本来就短（P25 会尽早把块移进已完成）。

### 33b 全屏画面

- **进入**：`ESC[?1049h`（备用屏幕）、`ESC[?7l`（关自动换行）、`ESC[?1000h ESC[?1006h`（只上报鼠标按键和滚轮，SGR 编码，见待确认 2），清屏。
- **退出**（正常退出、Ctrl+C 两次、出错、收到信号，都要走到）：关鼠标上报、`ESC[?7h`、`ESC[?1049l`，然后按当时的宽度把整段对话（已完成的块）写到主屏幕。异常退出也要恢复终端，挂在进程退出钩子上。
- **布局**：整个画面高度是 `rows − 1`（Ink 每帧后面会多写一个换行，加上它正好一屏）。上面是对话视图，自动占满剩余高度；下面是现在的底部区域（活动行、排队、输入框、菜单、提示、状态栏），组件不变。
- **对话视图**：把已完成块和正在变化块的行连起来，取一段显示。跟随底部时取最后一屏；往上翻时按偏移量取。视图用 Ink 的 `overflow="hidden"` 加底部对齐，所以不需要事先知道视图精确有几行：多给一些行，顶部超出的部分会被裁掉。
- **每帧原子化**：Ink 每帧调用一次 `stdout.write`。全屏时给 Ink 传一个包装过的 stdout，每次 write 前后加上 `ESC[?2026h` / `ESC[?2026l`，终端只显示整帧。
- **调整窗口大小**：清屏、重置 Ink 的行计数、按新尺寸重画一帧，都在一次同步输出里完成。画面只有一屏，所以代价很小，和历史长度无关；已完成块的行缓存按新宽度在需要显示时才重算。宽度和高度变化都这样处理。
- `/clear`：清空视图，也就是开一个新纪元，和现在一样。

### 33c 滚动

| 操作 | 行为 |
|---|---|
| 滚轮 | 每格 3 行 |
| PgUp / PgDn | 翻一屏，保留 2 行重叠 |
| Ctrl+Home / Ctrl+End | 到最顶 / 回到底部，并恢复跟随 |
| 提交一条消息 | 回到底部，并恢复跟随 |

- **跟随**：在底部时，新内容进来就跟着往下走；翻上去以后视图停住，输入框上方显示「↓ 下面有 N 行新内容 · Ctrl+End 回到底部」。
- 鼠标序列（`ESC[<64;x;yM` 等）在 `handleInput` 里先截下来处理，不交给编辑器；其他点击忽略。
- **↑↓ 仍然是输入历史**，和现在一样，不拿来滚动。

### 33d 开关与兼容

- **决定用哪种模式**：先看命令行 `--inline`、`--fullscreen`；没给就看 `settings.json` 的 `tui.mode`（`"fullscreen"` 或 `"inline"`）；都没有就用全屏。
- **不是 TTY 的情况**照旧：`-p`、管道、json、rpc、acp 都不受影响。
- `TAU_TUI_MODE=inline` 环境变量，给不方便改设置的场合（tmux 冒烟测试两种模式都要跑）。
- 扩展 API 不变：widget、header/footer、消息渲染器、工具渲染器照常工作。它们产出的 `StyledLine` 本来就是按行的，自定义渲染器返回的 Ink 元素在全屏视图里按 `blockLines` 的约定处理（见风险）。

## 验收清单

- [x] `blockLines` 单测：每类块在 40、80、120 列下的行，与改造前 `BlockView` 经 ink-testing-library 渲染的结果逐行一致（中文长行、带前缀的悬挂缩进、代码块不折行而是截断等现有行为一并保留）。
- [x] `LineCache` 单测：同一块同一宽度只算一次；宽度或 verbose 变了重算；`/clear` 后清空。
- [x] 视图单测：跟随时显示最后一屏；翻上去后新内容不移动视图，并显示正确的「下面有 N 行」；PgUp/PgDn/Ctrl+Home/Ctrl+End/滚轮的偏移；提交后回到底部。
- [x] 鼠标解析单测：SGR 滚轮上下、点击被忽略、半截序列不进编辑器。
- [x] tmux 冒烟（两种模式都跑现有 13 个场景）：
  - 全屏模式新增「调整宽度」场景：依次缩到 100、80、60 列再放宽，每次之后屏幕上只有一个输入框；录下的字节里不出现在旧帧上折行的痕迹（每帧以同步输出包住）。
  - 「滚动」场景：输出超过一屏后，PgUp 能看到更早的内容、Ctrl+End 回到底部。
  - 「退出」场景：退出后主屏幕上有完整对话，终端恢复自动换行和鼠标。
- [x] 异常退出：在 TUI 里让进程抛错或收到 SIGTERM，终端回到主屏幕且能正常输入。
- [x] 性能：200 轮的对话里，打字、流式输出时每帧耗时（不含终端）与改造前同量级；调整窗口大小一次在 20ms 以内（只重画一屏）。
- [x] 真机验收（用户）：Windows Terminal 里拖窄、拖宽，没有残影；滚轮翻看历史；退出后对话留在终端里。
- [x] DoD 通用项。

## 风险

- **`blockLines` 和 Ink 布局有细微差异**：换行位置、悬挂缩进的边界情况。缓解办法是改造前后逐行对比的测试，覆盖所有块类型，inline 模式也走同一条路，有差异会在两种模式里同时暴露。
- **扩展的自定义渲染器返回 Ink 元素**（`registerMessageRenderer` 等）：这些元素没法直接算出行数。全屏视图里先用 Ink 把它们单独渲染成字符串，再按行切开并缓存（只有用了自定义渲染器的块才这样做），inline 模式照旧。
- **鼠标上报让终端原生拖选需要按住 Shift**：Windows Terminal、iTerm2 和多数 Linux 终端都支持 Shift+拖选；文档和首次进入全屏时的提示里说明。
- **Ink 在整屏输出时会走自己清屏重写的分支**（输出高度不小于终端行数时）：所以画面高度定为 `rows − 1`。

## 实施记录

一个提交完成 33a–33d 与文档。全量 829 个测试，826 通过、3 跳过（连跑五遍全绿）；check、纯度门禁、pinned-deps、shrinkwrap、pack smoke 通过；smoke-tui 十七个场景（WSL tmux）在全屏和 inline（`SMOKE_TUI_MODE=inline`）下各跑一遍都通过；TUI 测试在 WSL Linux（Node 22）上也全部通过。新增测试：`blockLines` 与改造前 Ink 渲染逐行对比 105（17 个样本 × 40/80/120 列 × verbose，加样式与缓存）、wrap 移植与 wrap-ansi 对照 3（含 4000 条生成文本）、全屏 19（滚动输入、半截鼠标序列、视图切片、只渲染末尾、同步输出、调整大小重画、恢复终端、退出输出、模式选择、`/settings` → Screen、控制器滚动）、光标序列不当成警告 1。

**性能**（200 轮对话，每轮用户、工具、12 段的回答，中英混排）：跟随底部时调整宽度只渲染填满一屏的块，0.5–3 毫秒；整段重排（调整宽度后第一次往上翻时才做）约 135 毫秒，之后走缓存，0.5 毫秒。

与规格书不同、或规格书没写到的地方：

- **`blockLines` 返回带 SGR 样式的字符串行**，不是 `StyledLine[]`：Ink 的 `<Text>` 原样输出这些行，全屏视图一行一个 `<Text wrap="truncate-end">`。是否带颜色看 `stdout.hasColors()`（测试里没有颜色，与 Ink 的 chalk 一致）。inline 模式每块一个 `<Text>`，行用换行连起来，而不是一行一个。
- **折行移植了 wrap-ansi**（`render/wrap.ts`）。wrap-ansi 每个词、每个字符都调 string-width，每遇到一个转义序列就新建正则、切一次剩余字符串，200 轮的整段重排要 1.5 秒。移植版对可打印 ASCII 走快路径、转义扫描用一个 sticky 正则，连它的怪处（下一行只重开最后一个简单 SGR 码）也照搬；与 wrap-ansi 对 4000 条生成文本逐字节相同，长回答快 27 倍。放得下的行直接返回、不进折行。wrap-ansi 改为 CLI 的 devDependency，只在对照测试里用。
- **跟随底部时只渲染末尾的块**（`tailRows`），总行数在滚动时才数（`setViewport` 接受函数）。规格书写的是「多给一些行、顶部裁掉」，实际按行精确切片。
- **扩展的自定义渲染器不返回 Ink 元素**：消息、条目、工具渲染器产出的都是 `StyledLine[]`，风险里说的「先用 Ink 渲染成字符串」不需要。
- **改造前的 `BlockView` 移到 `test/ink-blocks.ts`**，只作 `blockLines` 的对照；`render/blocks.ts` 只留颜色、选项与底部区用的 `styledLine`。
- **鼠标报告统一在 `useInput` 那条路上处理**（`input/scroll.ts` 的 `takeMouseReports`）：滚轮滚动、点击丢弃、读到一半的报告留到下一次读入补齐，都不进编辑器。PgUp/PgDn、Ctrl+Home/End 仍从原始输入读（Ink 会吞掉 Home、End）。
- **模式的优先级**：命令行参数 > `TAU_TUI_MODE` > `tui.mode` > 全屏。规格书把环境变量单列，没写它和设置谁优先；环境变量是临时的，排在前面。`tuiScreen` 放在 settings.ts（main.ts 导入即运行，测不了）。`/settings` → Screen 写 `tui.mode`，保留 `tui` 里的其他键。
- **调整窗口大小**：每轮事件循环最多重画一次，停下 150 毫秒后再按系统报告的尺寸重画一次（Windows 可能先发事件后改尺寸）。冒烟里的尺寸是 100×38、70×30、50×24、110×40，宽高一起变；检查每次之后只有一个输入框、对话还在、写出的字节以同步输出加清屏开头。
- **异常退出**：挂在 `exit`、`SIGTERM`、`SIGHUP` 上；Ctrl+C 在原始模式下归 TUI。冒烟新增 SIGTERM 场景，退出与信号两个场景都检查备用屏幕和鼠标上报已关。
- **顺带修的问题**：
  - Ink 的 log-update 经 cli-cursor 把显示、隐藏光标写到 stderr，被 console 捕获当成警告，每次重画追加一条提示，把对话顶出视图；现在只含光标序列的写入原样交给终端。
  - 自 P25 起，退出 TUI 时在 `unmount()` 之后才取 `waitUntilExit()`，那个 promise 永远不会 settle，进程以未完成的顶层 await 退出（退出码 13），跳过了关括号粘贴和恢复 console。现在先取再卸载。
  - 测试里三处时序竞争：harness 固定等 30 毫秒再打字（负载高时丢第一个键），两个调整大小的测试用 30 毫秒的稳定时间（负载高时定时器先于 setImmediate）。改为等 Ink 挂上 stdin 监听，稳定时间加大并轮询。
- **CI** 的 smoke-tui 跑两遍：缺省全屏一遍，`SMOKE_TUI_MODE=inline` 一遍。

**未做**：搜索（待确认 4）、tau 自己的选中即复制、按终端类型自动降级、挂起（Ctrl+Z）、滚动条，都在范围外。真机验收：用户在 Windows Terminal 里确认残影消失；修掉调整大小时偶尔的闪烁后（见下）确认通过。

**真机反馈后的修正（2026-10-19）**：用户确认残影没了，但调整大小时偶尔闪一下。原因是重画顺序：先单独写清屏，再交给 Ink 画，而 Ink 每 32 毫秒最多画一帧，拖动窗口时新帧常常晚到，同步块又先结束了，终端就显示出空屏；另外 `log.done()` 会把光标显示一下，视图高度在布局之后才量出来，也会多出一帧旧比例的画面。改为：Ink 的每次写出都改写成从左上角整屏重画（每行清到行尾、最后清掉其余部分），从不先清屏；调整大小时排版后立刻调用 Ink 不节流的渲染；视图用 flex 占满底部区剩下的高度（跟随时底部对齐、翻上去时顶部对齐，多余的行由视图裁掉），量出来的高度只用于滚动和「下面还有 N 行」。冒烟的调整大小场景改为检查：写出的字节里没有清屏，每个同步帧都从左上角开始且包含输入框。
