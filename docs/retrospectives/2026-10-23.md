# tau 复盘（2026-10-23，P52）

> 范围与方法见 [P52 规格书](../specs/phase-52-retrospective.md)。这一阶段不改代码，只记录；后续做什么由用户从文末的候选里选。每条结论后面是它的出处，数据怎么得出的见附录。

## 一页概览

**现在是什么**：19 个包，源码约 70000 行、测试约 39700 行；其中 CLI 30100 行（TUI 占 15000），内核 15500 行。npm 上停在 2026-07-21 的 0.2.0。功能面已接近 Claude Code 的日常子集（MCP、LSP、钩子、子 agent、worktree、后台命令、定时、记忆……），参照的 pi（v1.4.0）与 Claude Code（2.1.308，最新 2.1.309）都是最新的。工程纪律在：纯度门禁、结构门禁、1372 个测试（覆盖率约九成）、38 个 TUI 冒烟场景、CI 自 P46 起全绿。

**最大的五个问题**：

1. **做得多，用得少，验证欠得多。** 真实会话 20 个、每个中位 1 轮，最近一次真实使用是 10-20；P34 之后加的功能几乎没有被真实用过。P34–P49 的真机验收 16 个阶段都没做。真端点验收屡次查出潜伏了好几个阶段的 bug，说明没被查出来的同类问题大概率还有。
2. **定位漂移。** 立项与主线计划都是「内核为主、产品层搁置」；P21 之后九天里 CLI 从 3400 行涨到 30100 行，内核从 6000 行涨到 15500 行，新增的内核代码多半是为 CLI 功能服务的。纯度门禁守住了「运行时无关」，但「内核项目」已经名不副实。
3. **发布停在三个月前。** 8 个包从没发过（技术债 #13 只登记了 4 个），已发的 11 个都是 0.2.0；`[Unreleased]` 有 1423 行。没有外部用户，也就没有外部反馈。
4. **节奏太快的痕迹。** 九天 32 个阶段、每天 21–34 个提交；CI 99 次运行失败 15 次（12 次在 P22–P45）；P35、P37、P39–P41 的验收清单基本没勾；P50 复查又查出 architecture.md 七处错；文档和给模型的提示里写着并不存在的 `--resume` 参数。
5. **依赖与安全。** `npm audit` 有 4 个高危：飞书 SDK 带进的 axios、follow-redirects 在已有的 ext-feishu、channel-feishu 依赖里；MCP SDK 只是开发依赖。TUI 的 Ink 落后三个大版本（5 → 8），React 18 → 19。

**建议先做**：停下加功能，先用起来、把真机验收补上（候选 A）；接着就定位和发布各做一个决定（候选 B、C）。52f 的 TUI 摘出若要做，先定接缝（候选 D）。

### 把 tau 的 TUI 摘出来覆盖 yo-agent：可行性

**两边的根本差别在接缝**。yo-agent 的 TUI 只依赖一个窄接口 `TuiKernel`（`src/tui/types.ts`）：订阅带游标的事件流、带幂等键提交输入、对审批请求做决定，外加十几个可选接缝（切模型、切档位、压缩、列会话、恢复、分叉、读事件），缺省时对应功能降级——所以它天然可替换。tau 的 TUI 直接拿着 tau 的对象：

| 依赖 | 数量 | 内容 |
|---|---|---|
| 内核导入 | 44 个名字 | `Agent` 类本身、`ExtensionRegistry`、会话类（`JsonlSessionRepo`、`restoreSession`、`SessionRecorder`）、表单函数、各种类型 |
| `Agent` 的方法与属性 | 24 个 | `prompt`（拉取它的事件生成器）、`steer`、`followUp`、`compact`、`navigateTo`、`askAside`、`setModel`、`setUi`、`extensionContext`、`messages`、用量与上下文…… |
| 扩展注册表的成员 | 20 个 | 命令、widget、快捷键、渲染器、页眉页脚，以及 `runSessionBeforeSwitch`、`notifySessionStart`、`runModelSelectBefore` 等钩子的触发 |
| main.ts 交给 TUI 的选项 | 30 个 | `buildAgent`、`resolveModelSwitch`、`sessionRepo`、`saveSetting`、`saveTrust`、`reloadExtensions`…… |
| CLI 根目录模块 | 9 个 | 会话标题、handoff、未提交改动检查、git 路径、`/diff` 数据、状态栏输入、打开链接、push 通知、设置 |

而且两边驱动方式相反：tau 的 TUI 调 `agent.prompt()` 拉事件，yo-agent 的内核是订阅事件流、审批作为事件发出再回调决定；事件形状也不同（tau 的 `AgentEvent` 对 yo-agent 的 `EventEnvelope`）。

**接缝建议**：照 yo-agent 的 `TuiKernel` 的思路给 tau 的 TUI 定一个 `TuiBackend`：会话（列出、打开、新建、分叉、树与标签）、运行（提交、插话、排队、中止、压缩、跳转）、状态（消息、用量、上下文、模型、思考、档位、工具）、事件订阅（统一的事件形状）、反向的界面请求（审批、选择、输入、表单）、可选的扩展面（命令、widget、渲染器、快捷键、钩子通知）。tau 侧写一个基于 `Agent` + `ExtensionRegistry` 的实现，yo-agent 侧写一个基于 `TuiKernel` 的适配；CLI 根目录那 9 个模块改成经选项注入。工作量大，是一个多步阶段。

**另一条路**：yo-agent 按主线计划已在收割模式、不再加阶段。如果目标只是「有一个最好的 TUI」，可以把 yo-agent 剩下的两个真实缺口（子 agent 详情、`--resume`）补进 tau，yo-agent 的界面不再维护，就不用做摘出。两条路怎么选取决于 yo-agent 还要不要作为独立产品存在。

## 附录：数据怎么来的

脚本在本阶段的 scratchpad（不入库），方法如下，可照做复现：

- **A 使用痕迹**：遍历 `~/.tau/sessions/*/*.jsonl` 与 `~/.tau/audit/*.jsonl`，只数条目类型、工具名、模型、日期与目录（临时目录合并计数），不读内容。
- **B 规模**：`git diff --numstat <空树> <提交> -- packages/<包>/src` 累加新增行，取 2026-07-15、10-15、10-17、10-19、10-21、10-22、10-24 之前最后一个提交。
- **C 代码扫描**：TypeScript 源码里的 `export` 声明逐个查其他文件是否提到；同名顶层函数；`TODO|FIXME|HACK|XXX`；空 `catch`；`as unknown as`/`as any`。
- **D 覆盖率**：`node --test --experimental-test-coverage --test-coverage-include='packages/*/src/**' --test-reporter=lcov …`（与 `npm test` 同一组文件），按包汇总 lcov。
- **其他**：`npm outdated --workspaces`、`npm audit --json`、`npm view @yophon/tau-<包> version`、`git ls-remote --tags https://github.com/earendil-works/pi`、`npm view @anthropic-ai/claude-code version`、`gh run list --limit 200`、`git log --since=2026-10-15`；yo-agent 对照读 `packages/surface-cli/src/` 与 `apps/yo-agent/src/args.ts`；tau 的 TUI 依赖用 TypeScript 语法树统计 `packages/cli/src/tui/` 的内核导入与 `agent.*`、`extensions.*`、`options.*` 访问。
